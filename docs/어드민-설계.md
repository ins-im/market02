# MMM MARKET — 어드민 설계도

쇼핑몰(손님 화면)의 각 도메인에는 **관리(어드민) 짝**이 있다. 여기에 운영 전용 기능(대시보드·설정)을 더한 것이 어드민 전체다. 공통 토대(레이아웃·UI 키트·ADMIN 가드)는 이미 구축됨.

> 원칙: 어드민 화면은 대응하는 **도메인 DB가 있어야** 만들 수 있다. 백엔드 DB(회원·카탈로그·견적·주문·세금계산서·설정)는 **모두 구축 완료**되어, 아래 모듈 대부분이 운영 중이다. 남은 것은 관리자·권한 세분화 정도.

## 모듈 한눈에

| 모듈 | 경로 | 목적 · 주요 기능 | 선행(필요 DB) | 상태 |
|---|---|---|---|---|
| **대시보드** | `/admin` | 운영 요약: 승인대기·입금대기·배송대기·세금계산서 대기·신규가입 카운트 → 각 화면으로 | 여러 도메인(점진적으로 채움) | ✅ 완료 (승인·입금·배송·세금계산서·신규가입·유효견적 카드) |
| **회원 관리** | `/admin/members` | 사업자 승인/반려, 전체 회원 목록·검색(이메일/상호/번호), 상세, 상태(활성·정지·탈퇴), 등급(회원도매가) | 회원 DB ✅ | ✅ 완료 (목록·검색·상세·승인·정지·등급) |
| **상품 관리** | `/admin/products` | 상품 CRUD·활성화, 옵션·색상·이미지, 대표가·**회원도매가** 설정, 카테고리, 홈 큐레이션(featured) 편성 | 카탈로그 DB ✅ | ✅ 완료 (CRUD·옵션·이미지·홈 편성) |
| **주문 관리** | `/admin/orders` | 주문 목록(상태·기간·검색), 상세(스냅샷), 입금확인(금액 표기 확인창), 상태 전이(입금대기→…→배송완료), 운송장·택배사, 취소/환불 | 주문 DB ✅ | ✅ 완료 (목록·상세·입금확인·상태전이·운송장·세금계산서 발행·취소/환불) |
| **견적서 관리** | `/admin/quotes` | 발행 견적 조회(고객·번호·기간), 상세, 유효기간(대부분 조회 위주) | 견적 DB ✅ | ✅ 완료 (목록·검색·유효/만료 필터·상세) |
| **세금계산서 관리** | `/admin/tax-invoices` | 신청 건 목록(발행대기/완료 탭), 발행완료 처리, 발행 내역 | 주문·세금계산서 DB ✅ | ✅ 완료 (목록·탭·발행처리) |
| **사이트 설정** | `/admin/settings` | 공급자 정보·입금계좌·**결제수단 노출 토글**(가상계좌/무통장입금)·견적 유효기간·고객센터 연락처 — `lib/constants` 하드코딩 값을 DB화해 편집 | 설정 테이블 ✅ | ✅ 완료 (DB화 + 편집 + 소비자 화면 연동) |
| **관리자·권한** | `/admin/staff` | 복수 관리자, 역할 세분화(현재는 단일 ADMIN) | 회원 DB ✅ | ⬜ 후순위 |

## 손님 화면 ↔ 어드민 짝 (매핑)

| 손님 | 어드민 |
|---|---|
| 상품 탐색·검색·상세 (`data/mock-*` → DB) | 상품 관리 |
| 회원가입·로그인·마이페이지/회원정보 | 회원 관리 |
| 견적서 발행·조회 | 견적서 관리 |
| 주문/결제·배송조회 | 주문 관리 |
| 세금계산서 내역 | 세금계산서 관리 |
| (하드코딩된 공급자·계좌·유효기간) | 사이트 설정 |

## 빌드 순서 (완료 이력)

아래 순서로 구축했고, **8번(관리자·권한)을 제외하고 모두 완료**되어 운영 중이다.

1. **상품 관리** ✅ — JSON 손편집 제거 + 회원도매가 어드민 설정. 다른 어드민 화면의 본보기(목록·폼·이미지 업로드 패턴).
2. **회원 관리 확장** ✅ — 승인 외 전체 회원 목록/검색/상세/상태.
3. **사이트 설정** ✅ — 설정 테이블로 하드코딩 값 제거(+결제수단 토글).
4. **대시보드** ✅ — 운영 지표 요약 카드.
5. **주문 관리** ✅ — 입금확인·상태전이·운송장·취소/환불·결제수단 이원화.
6. **견적서 관리** ✅ — 발행 견적 조회·필터·상세.
7. **세금계산서 관리** ✅ — 발행대기/완료·발행처리.
8. **관리자·권한** ⬜ — 복수 관리자·역할 세분화. 필요 시 착수(현재 단일 ADMIN).

## 공통 원칙 (모든 어드민 화면)

- **UI 키트 재사용**: `app/admin/admin.module.css`(테이블·카드·버튼·뱃지) + `StatusPill`·`AdminNav` + 앞으로 추가할 `DataTable`·`Toolbar`(검색/필터)·`Pagination`·`Modal`.
- **접근 가드 2중**: `proxy.ts`(낙관적) + 레이아웃/`getAdmin`(서버 확정). 모든 어드민 API는 `getAdmin` 재확인.
- **감사 흔적**: 누가 언제 처리했는지 기록(예: 승인의 `approvedById`/`approvedAt`). 주문 상태변경 등에도 확장.
- **목록 공통 패턴**: 검색 + 필터 + 정렬 + 페이지네이션 (상품·주문·회원이 공유).
- **CSS Modules 유지** — 유틸리티 프레임워크 미도입, 공유 키트로 반복 최소화.
- **쇼핑몰과 UI 완전 분리**, 데이터·도메인 로직(`server/**`)은 공유(단일 진실).

## 결정됨 / 미정

- **이미지·파일 업로드 스토리지** — ✅ **Supabase 서울(ap-northeast-2) Storage로 확정·운영 중** (상품 이미지·사업자등록증 공통).
- 재고 관리 도입 여부 — 미정 (현재 스키마에 재고 없음 — 필요하면 Variant에 stock 추가).
- 관리자 여러 명·역할 세분화 시점 — 미정 (현재 단일 ADMIN).
